# 工作台对话体验实施流程

状态：实施中。日期：2026-09-18。

本文件是执行入口；唯一行为规格为 [工作台对话体验优化方案](../docs/workbench-conversation-experience-plan.md)。先阅读规格相关章节，再执行下列任务。不要把文档完成视为功能已交付。

## 执行顺序

| 任务 | 内容 | 阻塞依赖 | 优先级 |
| --- | --- | --- | --- |
| W00 | 基线、缺陷复现与可交互视觉原型 | 无 | P0 |
| W01 | 完整回答、Markdown 与滚动连续性 | W00 | P0 |
| W02 | 取消常驻右栏、统一图片参数与单张默认 | W00 | P0 |
| W03 | 运行／工具／成果事件和旧历史兼容 | W01 | P0 |
| W04 | 工具参数、对象与确认准确性 | W02、W03 | P0 |
| W05 | 副作用去重、局部失败、停止与恢复 | W04 | P0 |
| W06 | 文档编写、展开、阅读与编辑闭环 | W03、W05 | P1 |
| W07 | 提示词／图片成果、输入与整体视觉动效 | W01、W02、W06 | P1 |
| W08 | 内存／缓存／长会话与检索联合回归 | W05、W07 | P1 |
| W09 | Electron 验收、工具评测与交付 | W08 | P0 发布门槛 |

依赖表示功能先后，不要求多个 Agent 并行。W01、W02 可分别实现；共同文件修改仍需协调。W00 的原型只用于验证布局与交互，不直接替换生产业务代码。

建议验收批次：A=W00–W02（最明显体验问题）；B=W03–W05（执行可靠性）；C=W06–W08（完整工作台体验）；W09 统一决定是否达到交付条件。

## 每个任务的统一执行流程

1. 阅读相关生产代码、现有测试及本任务依赖的验证证据。记录起始工作树，不回退已有未提交修改。
2. 确认可观察目标；缺陷先写最小失败复现并运行。纯视觉调整记录修改前截图和操作路径，不写只检查源码字符串的无效测试。
3. 修改前运行相关现有测试，记录已有失败；按一个行为切片实现，不同时重构无关链路。
4. 运行新增及相关回归；UI 在真实 Electron 中验证，浏览器原型不替代文件／IPC／持久化验收。
5. 代码交付运行仓库要求的 TypeScript、完整单元测试、文件大小检查、网页生产构建和 Electron 生产构建；以当时 `package.json` 为命令真源。涉及 UI 的任务验证规定尺寸及明暗主题。
6. 在本任务证据栏写入命令、结果、截图／报告路径、剩余风险；全部标准满足才勾选。未接通的行为继续明确标为模拟。

下一次执行从 W00 开始。无需重新设计整套方案；仅在复现证据或原型结果推翻某项假设时更新规格对应章节并说明原因。
