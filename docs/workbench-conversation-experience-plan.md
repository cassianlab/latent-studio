# 工作台对话体验优化方案

日期：2026-09-18。状态：待实施的产品与工程方案；本文件不表示功能已经完成。

执行入口：[工作台体验实施流程](../tasks/workbench-experience-rollout.md)。产品边界沿用 [Latent Studio 升级方案](Latent%20Studio%20升级方案.md)；本方案细化工作台对话、工具执行与成果展示，不替代已有阶段任务。

## 1. 目标与设计取舍

工作台应让用户能够连续表达、看到完整回答、理解执行状态，并直接使用结果。文档、提示词、图片是对话中的成果；操作它们之后，对话仍能自然继续。

本轮建议采用以下默认行为，原型阶段验证具体尺寸和密度：

- 取消工作台常驻右侧检查器及其占位；常用控制归入输入区，详细设置按需打开。
- 新会话生图默认一张。当前消息明确数量优先；普通 Agent 对话不被默认图片参数约束。
- 完整保留回答与推荐理由，结果卡片作为补充；执行过程默认收纳成一行可展开状态。
- 文档完成后默认显示紧凑成果条，用户可在对话内展开、独立阅读、编辑，也可设置自动展开新完成文档。
- 用真实阶段和结果驱动反馈；停止、失败、部分成功、等待确认都具有独立语义。
- 保留中文、暖白／近黑／克制红色、系统中文字体及现有组件基础；不引入新的视觉主题或通用 Agent 工作流框架。

取舍：移除右栏会减少参数的持续可见性，以输入区参数摘要弥补；文档折叠减少滚动长度，以显式展开和用户偏好补足；资源卸载减少内存，以少量按需重读换取稳定性。不会通过隐藏错误、删掉回答或虚构进度改善表面观感。

## 2. 现状证据与待验证风险

以下为当前工作树的代码检查结果，不能替代 Electron 运行复现。历史截图中的所有异常尚未逐一重新复现。

| 项目 | 已观察到的实现 | 影响与处理方向 |
| --- | --- | --- |
| 推荐理由消失 | `src/main/agent/runner.ts` 最终搜索回复被替换成固定句；`src/renderer/agent/agent-conversation-model.ts` 再替换一次 | 同时修复数据来源和展示，两处都保留模型最终正文；更新现有期望固定句的测试 |
| 文本格式不足 | `AgentConversation.tsx`、`TextConversation.tsx` 按换行生成段落 | 统一安全 Markdown 渲染、链接路由与消息操作 |
| 阅读位置被打断 | 两个对话组件随文本变化调用 `scrollIntoView`；`src/App.tsx` 按会话和模式 key 重挂载线程 | 底部跟随、向上阅读保护、恢复滚动与展开状态；避免模式切换重播整段动画 |
| 右栏占据空间 | `src/App.tsx` 默认 `inspectorCollapsed=false` 且工作台挂载 `Inspector`；折叠后仍有侧条 | 移除工作台占位，按能力迁移有用控制，检查其他页面引用后再决定是否删除组件 |
| 无效配置干扰 | `Inspector.tsx` 有标记“暂未支持”的 Steps、CFG、Seed、负面提示词等禁用控件 | 工作台隐藏不能发送的控制；设置详情保留真实能力说明 |
| 四张默认值 | `WorkbenchComposer.tsx` 初始化为 `4 个`，Agent／图片提交带上数量；`ImageConversation.tsx` 有 `智能变体 · 4 张` 回退文案 | 默认值、提交意图和展示文案一起修复，建立一个有效参数来源 |
| 文档流式信息缺口 | `src/main/agent/ipc.ts` 的 `streamText` 仅转发 `text_delta`；底层文本契约已有工具参数增量 | 需要新增经过筛选的文档草稿／工具状态事件，才可显示真实编写预览 |
| 已有可复用能力 | `MarkdownViewer`、`DocumentViewerModal`、`DocumentEditorModal`、项目文档读写工具已存在 | 扩展现有能力；先检查流式渲染、安全链接、版本兼容，再决定抽取范围 |
| 部分提交风险 | `runner.ts` 通过 `Promise.all` 创建图片任务，全部返回后才加入运行记录 | 单项失败时可能已有任务入队；先故障注入复现，再设计逐项记录与去重 |
| 操作范围风险 | `controlTasks` 的暂停／恢复使用队列级方法 | “停一下”应作用于当前运行；全队列操作必须有明确意图与范围 |
| 确认与恢复风险 | 运行有 `session.confirmed` 状态；前端加载待确认运行需要核查会话隔离 | 测试多工具确认、取消、切项目、重启恢复，不能把可能风险当作已复现事故 |

已有检索缓存、索引和上下文提示移除改动不在本轮推倒重做。把提示词库更新、分组切换、向量安装／卸载作为联合回归场景；只有新证据指向该链路时才扩大修复范围。

## 3. 整体布局与视觉规范

### 3.1 默认工作台

```text
┌──────────────┬────────────────────────────────────────────────────┐
│ 项目／会话    │ 会话标题                         搜索会话   更多     │
│ 可折叠导航    ├────────────────────────────────────────────────────┤
│              │ 用户：帮我挑适合产品海报的提示词，并说明理由。         │
│              │                                                    │
│              │ Agent：我推荐这三个方向……                          │
│              │ 1. 极简棚拍：适合突出材质……                         │
│              │ 2. 场景叙事：适合展示使用方式……                     │
│              │ [提示词 1 · 查看／使用] [提示词 2 · 查看／使用]       │
│              │ [已完成 · 检索 1 次                 展开执行详情]   │
│              │                                                    │
│              │ [文档：海报方案 · 已保存   展开  阅读  编辑  更多]     │
│              │                                                    │
│              ├────────────────────────────────────────────────────┤
│              │ 继续讨论或提出修改……                              │
│              │ 附件／参考图摘要                                   │
│              │ [Agent] [模型] [工具／权限] [图片设置（按需）] [发送]│
└──────────────┴────────────────────────────────────────────────────┘
```

右侧无常驻窗口、折叠把手或预留空白。执行状态在运行中靠近当前回复；完成后弱化收纳，不改变正文与成果的对应关系。

| 区域 | 行为规范 |
| --- | --- |
| 顶部 | 会话标题、必要导航和低频菜单；上下文正常读取保持安静。实际读取失败才提供简短说明与修复入口 |
| 对话 | 正文建议宽度 720–840 CSS px，中文阅读密度以原型实测调整；图片／表格允许更宽；短回答不套大卡片 |
| 输入区 | 与正文对齐，固定在内容底部且不遮挡消息；主操作只有发送或停止；高级参数在 popover 内 |
| 参考素材 | 以可移除缩略图／文件条展示，显式区分本轮附件和沿用的参考图；点击可查看真正的引用对象 |
| 生图摘要 | 生图模式显示模型、数量、比例；Agent 中作为可选工具配置，只有生图动作使用；非支持参数不伪装成有效值 |
| 文档／图片 | 点击才打开阅读器；默认对话内预览或独立大阅读器。宽屏可主动选择“并排阅读”，关闭后完整恢复对话宽度 |
| 设置 | 模型连接、并发、全局记忆管理进入现有设置／资料页；工作台只显示与本次任务有关的状态 |

1024×720：导航可折叠，阅读器覆盖内容区，不挤成三栏；1440×900：舒适单列；1920×1080：限制正文行宽，用户主动并排时才分栏。三种尺寸分别验收明暗主题，长中文标题、长路径、代码和放大字体都不撑破布局。

视觉建议：正文 15–16px、行高 1.6–1.75，辅助说明 12–13px；沿用 4／8 间距基础。普通文本对比度至少 4.5:1。图标沿用 Lucide；红色保留给主操作强调和危险反馈，并用文字区分含义。桌面控件可见尺寸建议 28–32px，交互命中区至少 32px；避免只有悬停才能发现的核心操作。

### 3.2 动效与可访问性

| 场景 | 建议反馈 | 约束 |
| --- | --- | --- |
| 按下、发送、停止 | 立即改变按钮状态；微反馈约 100–140ms | 本地操作反馈目标小于 100ms，状态不得等待动画结束 |
| 新消息到达 | 一次轻淡入，约 140–180ms | 历史加载、主题／模式切换不逐条重播；不对每个 token 播动画 |
| 工具阶段变化 | 稳定一行文字与小状态图标；阶段切换可短淡入 | 无真实总量时不显示百分比，不显示模型内部推理 |
| 编写／编辑文档 | 标题旁轻量活动标识；有真实内容增量时更新预览 | 草稿与已保存清楚区分，失败后停止动画并保留可恢复内容 |
| 展开成果 | 立即完成布局更新，可给内容轻淡入并保持滚动锚点 | 不持续动画大段高度，不自动抢焦点 |
| 阅读器打开／关闭 | 约 160–220ms 的局部过渡 | 保留现有遮罩无 blur 约束；可中断，关闭后焦点回触发按钮 |

遵循系统“减少动态效果”；只保留静态状态或极短淡入。状态变化用合适的 `aria-live` 汇总，避免逐 token 朗读。键盘支持 Tab、Esc 关闭浮层、返回触发点；发送快捷键避免与中文输入法确认冲突。快捷键提示、可见焦点、禁用原因均需可访问。

## 4. 对话与成果行为

### 4.1 消息连续性

- 每条回复可由正文、执行摘要、提示词／文档／图片成果组成，绑定同一个消息 ID；新增成果不覆盖正文。
- 工具前的简短说明和工具后的结论分清顺序；技术事件不是普通消息。不要用整条 `text_reset` 擦除已展示的有效回答。
- Markdown 支持常用标题、列表、表格、代码、引用、链接；流式未闭合语法以可读文本保底，结束后格式稳定。复制取得原正文。
- 项目文档链接按项目 ID 和相对路径经受限业务 API 打开；外链沿用安全打开策略。拦截任意本地路径、脚本协议和越界访问；Renderer 不获得通用文件权限。
- 用户在底部时跟随新内容；向上阅读时停止跟随，显示“有新内容／回到底部”。展开文档、图片加载、历史分页保持锚点。
- 输入草稿按项目／会话保存；发送被拒绝时恢复；运行中仍可编辑下一条。首版明确使用“停止后发送”，排队发送作为后续增强，不暗中并发同一会话。
- 新建项目／会话显示简洁欢迎语和少量可点击示例；仅对确实缺失的模型配置提示设置。不得出现虚假的历史继承说明、旧项目任务或调试信息。
- 编辑并重新提交历史提问时明确新分支；历史工具副作用不自动重放。支持复制、重试、继续修改；存储分支复杂度过高时先提供“编辑为新消息”，不伪称已有分支能力。

### 4.2 提示词推荐

正文保留每项推荐理由、适用场景与必要差异；卡片负责标题、来源、预览和使用操作。正文引用与卡片用稳定结果 ID 关联，编号只作本轮显示顺序。

默认展示紧凑列表和有限首屏结果，用户可切缩略图视图、展开更多、查看完整提示词；界面折叠不改变模型已引用的结果顺序。“使用第二个”解析最近有效结果集的第二项；不从当前全局列表重新猜测。检索系统的匹配说明和模型推荐理由分开，避免混淆来源。

没有结果时解释范围，允许改关键词／扩大范围；服务失败时可保留已有结果并标记。正文缺失才使用简短后备文案，不能覆盖实际回答。旧会话若运行记录仍有正文可恢复；原文已丢失则保留现存内容，不伪造历史推荐理由。

### 4.3 文档全生命周期

```text
准备内容 → 草稿编写／修改 → 等待确认（需要时） → 保存中 → 已保存
     任意执行阶段 → 已停止／失败（保留可用草稿，展示实际保存情况）
```

| 阶段 | 用户看到的内容与选择 |
| --- | --- |
| 草稿生成 | “正在编写《名称》”及可展开预览；底层无内容增量时只显示真实阶段，不假装逐字打字 |
| 修改已有文档 | “正在修改《名称》”；保存前提供本次修改摘要，必要时可查看差异；原版本在写入成功前保持可读 |
| 等待确认 | 显示准确目标与修改摘要；用户可确认或取消，取消不留下成功标记 |
| 已保存 | 紧凑成果条：“名称 · 已保存”，包含展开／收起、独立阅读、编辑、更多；Agent 继续解释完成了什么 |
| 部分失败 | 保留已保存成果；失败项提供对应重试。草稿标注“尚未保存”，可以复制或另存 |
| 再次打开历史 | 展示当轮成果版本的可用快照／摘要；“打开当前文档”指向最新版本，二者名称明确 |

展开偏好提供“默认收起”和“完成后自动展开”。逐条开合覆盖当前项，历史记录加载不批量展开；用户在别处阅读时不强行滚动到新文档。大文档先渲染摘要或分段，正文按需读取；不把每版全文重复塞进消息、工具事件和缓存。

同时打开编辑器和 Agent 修改同一文档时，用版本校验阻止静默覆盖，保留用户草稿并允许重新加载／比较。文档更新事件只刷新受影响成果；已删除文件仍有历史摘要，打开时如实提示。

## 5. 图片数量与参数规则

数量来源必须可追踪；不能用 `count=4` 同时表达系统默认、历史偏好和当前用户意图。

| 优先级 | 来源 | 行为 |
| --- | --- | --- |
| 1 | 本轮文字明确数量，例如“生成两张” | 使用 2，并在生图执行摘要展示；若与界面不同，说明采用本轮要求 |
| 2 | 本轮用户主动选择的数量 | 仅本轮生图适用；普通聊天不变成生图请求 |
| 3 | 明确修改上一张且无新数量要求 | 默认 1，只引用对应图片；本轮主动选多张则按第 2 级处理 |
| 4 | 没有明确数量 | 新创作默认 1；新会话不继承上次批量数量 |

首版默认不自动记忆批量数量；会话内正在编辑的数量草稿可保留，发送成功后恢复一张。比例等偏好可记忆，但有效值必须经过当前模型能力校验。数量大于一才出现“同提示词多张／智能变体”选项。

“三视图”默认理解为画面内容，不等同三张；“第 4 个”是结果引用；“四个人”是主体数量；“不要四张，只要一张”按一张。“几个方案”先判断是否只是讨论；真正要提交且数量不明时进行一次简短澄清，不能固定取四。

通过同一有效配置读取、展示并发送模型、数量、比例、分辨率、质量、格式和参考图；由主进程再校验能力与边界。移除右栏后不再靠多个局部 state 和 window event 互相同步。保留现有计划数量校验、参考图能力校验，不以改默认值绕过它们。

## 6. 工具调用准确性与执行体验

### 6.1 一次执行的约束

```text
理解本轮目标及明确引用
  → 提供当前模式／权限／能力允许的工具
  → 模型选择工具与参数
  → 主进程校验参数、对象、作用域和确认状态
  → 执行并记录已发生的副作用
  → 将真实结果提供给模型和界面
  → 生成解释与可操作成果
```

准确性同时包括：该不该调用、选什么工具、参数是否正确、操作哪个对象、先后依赖是否满足、是否重复、最终说明是否有结果依据。只调整提示词不能保证这些条件。

| 层次 | 实施要求 |
| --- | --- |
| 工具定义 | 用清晰名称、必要参数、能力说明和真实返回结构；读、创建、修改、删除区分；失败携带可纠正原因 |
| 工具选择 | 延续现有模式／权限过滤；普通问答允许零工具调用；查询类任务不写数据。Skill 延续候选元数据→显式激活→完整指令的 ADR-0006 机制 |
| 对象绑定 | 项目、会话、运行、工具调用、文档／提示词／图片任务均使用稳定 ID；“刚才那个”映射当前会话证据，歧义时澄清 |
| 参数校验 | 主进程检查 schema、范围、模型能力、路径归属与文档版本；工具结果、文档内容不提升权限；非法参数不能先执行后报错 |
| 执行顺序 | 写入依赖先读到正确对象，生图依赖提示词和参数就绪；只有互不依赖的只读步骤可考虑并发；不引入全新调度框架 |
| 纠错重试 | 参数错误只允许有限纠正，建议同一调用最多一次；只读瞬时失败可按服务策略重试。已提交但结果未知的写入先核对记录，不能整轮盲重跑 |
| 重复控制 | 用持久化操作标识记录副作用；图片按计划项记录 taskId；同一调用重送返回已知结果。用户明确“再生成一次”创建新操作标识 |
| 确认 | 每次确认绑定具体调用、目标和参数版本；确认一项不授权后续不同写入。保留现有权限／破坏性确认，普通读取不增加弹窗 |
| 停止 | 停止当前运行的模型流和未执行步骤；已提交图片逐项尝试取消；无法撤销的已完成写入如实保留。界面区分“正在停止”和“已停止” |
| 全局操作 | 当前任务的“停止／重试”不控制其他会话；暂停整个图片队列只通过明确的全局动作；按对象检查 taskIds 所属范围 |
| 重启恢复 | 根据持久化结果核对已完成／待确认／结果未知步骤；不会仅凭旧 running 状态自动重新执行写操作 |
| 结果解释 | 创建文档要有保存结果，生成图片要区分“已入队”和“已生成”；部分成功逐项报告，工具失败不能变成“运行完成” |

工具日志供排查使用，默认收起，仅展示用户可理解的阶段与目标；原始 JSON、供应商响应、完整提示词和技术栈细节不进入普通对话。日志记录耗时、脱敏参数摘要、结果 ID 和错误分类；限制保存量，不写密钥和大块二进制。

### 6.2 运行状态与事件

界面状态至少区分：准备中、生成回复、执行工具、等待确认、正在停止、已停止、部分完成、已完成、失败。Agent 执行结束和已创建图片任务完成分别跟踪，避免两套生命周期互相覆盖。

在现有窄 IPC 契约上补充必要事件，建议包括工具开始／结果、确认请求、文档草稿／保存、运行终态。事件带项目／会话／运行／步骤标识与顺序号，重复与迟到事件不能覆盖终态或串到其他会话。最终快照用于对账，流事件用于体验；为旧历史保留读取兼容。

文档预览仅发布白名单工具中可安全呈现的 title/content 增量；工具参数 JSON 不完整时缓冲解析，设置体积上限。保存成功前不产生“已保存”事件。无需把所有工具参数原样广播给 Renderer，也无需引入全量事件溯源架构。

## 7. 性能、缓存与检索连续性

性能是交互验收的一部分。用户此前报告的约 1.02 GB RAM 是待复测参考值，不作为当前基线或已优化证明。

- 区分持久化数据与临时资源：会话、文档和检索索引保留；离开页面卸载不可见缩略图、图片解码对象、Blob URL、监听器及大文档预览。
- 缩略图采用有容量上限的缓存，离开提示词库取消本页请求并释放视图引用；返回时读取本地缓存。不可删掉正在被工作台使用的参考图／共享资源。
- 文档折叠卸载重预览而保留元数据与展开偏好；重新展开按需读取。流式文本按帧或短间隔合并更新，完成时补齐尾部，避免每个 token 重渲染整个历史。
- 长会话先以稳定消息 ID、分段加载和局部更新控制成本；实测 DOM／内存瓶颈后才引入虚拟化，验证可变高度、选中文本和锚点。
- 普通检索继续使用持久化词法索引；向量可用且兼容时启用混合检索，安装中／不可用／卸载后正确回退。索引按条目更新，不按每次检索复制一套；新模型索引构建期间保留可用检索路径。
- 提示词仓库第一次可全量建立；后续先检查源版本／文件变化，再更新变更项。上游仅提供全量包时区分网络下载与本地重建，不能承诺零全量下载；无变化时跳过重新解析／建索引。
- 指标拆分 Electron Main、Renderer、GPU、Network；JS 堆、RSS 和物理 footprint 分开记录。JS 对象释放不保证操作系统立即回收 RSS，不能用单次 RSS 数值判断泄漏。

同机同数据至少进行三轮冷／热对照，以下为待基线校准的初始预算，变更需注明原因：

| 场景 | 初始验收预算／判据 |
| --- | --- |
| 本地发送、停止、展开按钮 | p95 可见反馈 ≤100ms；模型首 token 与网络耗时单独记录 |
| 分组切换、会话切换 | 本地首屏 p95 ≤300ms；内容未到时立即反馈，连续操作不失效 |
| 流式回答与滚动 | 目标 60fps；记录超过 50ms 的长任务，消除连续主线程阻塞；不强迫滚动 |
| 200 条消息＋20 个成果、10 次进出提示词库 | 完成资源释放与稳定观察后，JS 堆／资源计数无持续线性增长；受控 GC 测试的保留堆增量目标 ≤15%，排除有上限的预热缓存并报告绝对值 |
| 仓库未变化更新 | 解析／索引写入数为 0；记录版本探测耗时，不混入下载耗时 |
| 少量提示词变更 | 索引变更数与真实变更对应；查询不等待整库重新构建；记录实际库规模和冷／热延迟 |

工具评测分两层：确定性测试保证主进程校验、范围、去重、取消和状态正确；固定语料的真实模型评测检验选择、参数和必要性。固定语料至少 40 条，覆盖上表工具场景及中文表述变体，每条每个声明支持的代表模型运行 3 次，记录模型／版本／设置、调用、结果、耗时与失败类别。

初始发布门槛：关键确定性用例 100% 通过；真实模型端到端任务成功率目标 ≥95%；样本中跨项目误操作、未授权写入、重复创建和虚假成功为 0。报告总体、分场景和最差模型结果；达不到门槛则继续修正或明确限制支持范围，不能靠平均值掩盖高风险失败。该指标是验收目标，不是目前已有测量结果或对所有模型的保证。

## 9. 兼容性与实施边界

优先增量修改现有组件／服务，复用现有 React、Radix、Motion、Vitest 和文档读写能力。旧会话逐条兼容读取，避免启动时全库重写；缺少新成果字段时用现有正文与工具结果回退。

持久化操作标识、事件版本和文档快照保留策略涉及存储边界，实施前形成 ADR，明确迁移、体积上限、失败恢复和旧版兼容。操作去重只能保证本地已记录的副作用；外部供应商请求结果未知时显示待核对状态，不承诺无法实现的全局 exactly-once。

发布按可验证的纵向切片推进：先纠正内容丢失、四张默认和右栏布局，再完善执行事件与工具可靠性，之后交付文档体验和整体动效。每阶段都须保持应用可运行，不用一次性重写整个工作台换取新外观。

方案使用 ask-matt 的“规格→视觉原型→依赖任务→实现／验证”路径，任务沿用仓库 `tasks/` 约定；使用 UI UX Pro Max 的按需披露、阅读宽度、动效、可访问性与性能规则。技能搜索返回的营销布局／紫色主题与本产品不符，未采纳；渐进披露搜索未命中有效条目时采用其规则参考及上述项目证据，不把检索推荐当作产品事实。
