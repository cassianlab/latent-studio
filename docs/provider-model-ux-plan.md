# 供应商配置与模型选择优化方案

日期：2026-09-19
状态：已实施核心优化；供应商优先选择、严格模型路由、图片参数与提示词优化入口已完成。
依据：现有代码、ADR-0003、产品升级方案，以及 ask-matt 流程建议和 UI/UX Pro Max 的表单反馈、渐进展示、键盘导航建议。

## 1. 目标与明确约束

1. 配置过程能顺畅完成：添加供应商 → 配置连接 → 获取候选 → 选择并确认 → 工作台使用。
2. 文本和图片选择器均先选供应商，再选该供应商下的模型；禁止默认把所有供应商的模型铺成长列表。
3. 同一个模型由不同供应商或多个 Key 提供时，能辨认来源，请求始终使用用户选定的连接。
4. 100–500 个候选模型时仍能搜索、筛选、批量处理，保存后位置和选择不丢失。
5. 保留简体中文、暖白/近黑/克制红色和桌面应用形态，沿用 Electron 主进程、Preload、Renderer 边界。
6. 删除图片参数中的“变体与扩写文本渠道”，直接复用已选文本模型；提示词优化窗口中的文本模型选择也必须覆盖供应商分组。

本轮优先解决模型管理与使用链路。自由标签体系、价格比较、自动挑选最便宜渠道、跨供应商自动故障转移不进入首轮。

## 3. 设置页：供应商、连接、模型分层

### 信息架构

设置顶部只保留三个清晰入口：**供应商与模型 / 默认模型 / 通用**。窗口关闭行为移到通用；全局默认模型在独立页签集中管理。

供应商与模型页面：

```text
供应商与模型                                  [+ 添加供应商]
┌─────────────────┬──────────────────────────────────────┐
│ 搜索供应商       │ 创作中转                         [···]│
│                 │ 连接：[日常创作 ▾]       [+ 添加连接] │
│ OpenAI 官方     │ 地址摘要 · 密钥已配置 · 最近检测状态 │
│ 创作中转    ←   │ [检测连接] [编辑连接]                 │
│ 本地服务        ├──────────────────────────────────────┤
│                 │ 已添加模型          [从供应商导入]  │
│                 │ 搜索模型   全部 / 文本 / 图片        │
│                 │ 名称 / 模型 ID / 类型 / 能力 / 操作 │
│                 │ …                                    │
└─────────────────┴──────────────────────────────────────┘
```

左侧供应商只显示名称、连接数、已添加模型数。右侧一次显示一个连接，避免多个 Key 卡片各自展开几十个模型。单连接时显示连接摘要，多连接时出现切换器。供应商菜单和连接菜单各自管理对应实体。

名称统一：用户面对的是“供应商”和“连接”；API Key 是连接的一个字段。避免交替使用“分组、Key、渠道”指同一个层级。模型来源展示格式为“供应商 · 连接”。供应商按用户配置的供应商实例 ID 分组，不能按 `openai-compatible` 等协议类型合并。

### 添加与编辑流程

1. 点击添加供应商，选服务商预设或自定义，填写名称、地址和首个连接的密钥。
2. 高级区域包含连接备注、协议和并发。默认并发沿用 1。
3. 主按钮“保存并获取模型”，次按钮“仅保存”。创建供应商和首个连接作为一个本地事务；网络获取失败后保留已保存配置，并提供重试/手动添加。
4. 已有供应商可继续添加独立连接，不强迫每次重建供应商。
5. 检测结果准确区分“鉴权/模型目录可访问”和“具体模型已验证”。模型列表接口不支持时仍允许手动添加，不误判生成能力不可用。
6. 改供应商预设不静默修改现有连接；连接详情展示真正生效的地址/协议。批量应用预设若以后加入，必须列出受影响连接再执行。
7. 字段级错误就近展示；失败保留输入；保存期间锁定当前操作，成功后局部更新。

### 候选导入窗口

使用一个大尺寸对话框承载候选模型。标题明确当前供应商与连接，顶部固定搜索/筛选，底部固定导入操作；内部列表独立滚动。

- 筛选：全部、文本候选、图片候选、待确认、已添加。类型推测必须可见且可改。
- 列：选择、名称/原始 ID、类型、能力确认状态、已添加状态。长 ID 可查看完整内容。
- 已添加项按当前连接 + 原始模型 ID 对照；同模型在其他供应商下存在不算重复。
- 支持“选择当前筛选结果”，明确选择数和作用范围。初次导入不默认全选。
- 分页只选择已加载的筛选结果；按钮明确写“选择已加载结果”。支持加载更多，后续页失败不清空已加载内容。
- 批量设为文本/图片；未知类型必须确认后才能导入。无法用于本产品的音频、嵌入等候选保留为不支持项，不自动当文本导入。
- 第一阶段使用分页/分批渲染限制行数，基于 500 项场景测量后再决定是否引入虚拟列表依赖。
- 批量调用由主进程一次接收：逐项校验，返回新增/已存在/失败及原因；采用显式部分成功语义。成功项保留，重试仅处理失败项；本地写入事务失败则本批次回滚并说明。
- 导入结束保留窗口与滚动位置，显示“已添加 18 · 已存在 2 · 失败 1”，提供“重试失败项”和“完成”。
- 网络鉴权错误、网络超时、协议不支持、返回空目录分别给出具体下一步。

### 模型详情

点击模型行打开详情侧栏：显示名称、原始 ID、用途类型、绑定连接和能力开关。主列表保持精简。

能力分“供应商/适配器声明”“用户确认”“待确认”。名称推测只能提供建议；不能默认启用工具调用、视觉、原生搜索、多参考图。编辑显示名称时保留其他能力。改变类型时展示受影响能力和默认模型引用，确认后原子保存。

## 4. 工作台：先选供应商，再选模型

### 选择器布局

桌面使用单个面板内的左右两栏，避免依靠悬停展开的级联菜单：

```text
选择文本模型
┌───────────────┬─────────────────────────────────────────┐
│ 供应商        │ 搜索当前供应商的模型                    │
│               │ 连接：全部 / 日常创作 / 备用             │
│ OpenAI 官方   │                                         │
│ 创作中转   ←  │ GPT-4o                                  │
│ 本地服务      │ gpt-4o · 日常创作                    ✓  │
│               │ GPT-4o                                  │
│               │ gpt-4o · 备用                           │
└───────────────┴─────────────────────────────────────────┘
当前：GPT-4o · 创作中转 · 日常创作             管理模型
```

行为要求：

1. 打开时定位到当前所选模型所属供应商，并让当前行可见。
2. 左侧只列供应商及当前用途的模型数量，右侧只列当前供应商模型。
3. 点击供应商仅改变浏览范围；点具体模型才提交选择并关闭。
4. 多连接时提供连接筛选，每个模型行常显连接名；连接不是必须经过的第三步。
5. 默认搜索当前供应商；显式切换“跨供应商搜索”后，结果仍按供应商分段，始终显示连接。清空或退出搜索后恢复先供应商后模型的布局。
6. 文本和图片共用选择器结构与来源标签，各自过滤用途。
7. 收起按钮常显“模型名 · 供应商”；同一供应商内同名模型再显示连接名。长名称可以截断，但完整来源通过焦点/悬停详情可查。
8. 无可用模型时提供“添加模型”入口；供应商在某用途下没有模型时显示 0 和空状态，不无提示跳转到其他供应商。
9. 选择器键盘可打开、供应商可切换、模型可上下移动、Enter 选择、Escape 关闭，并把焦点还给触发按钮。不要只添加 listbox ARIA 而缺少键盘行为。
10. 狭窄空间改为两步面板“供应商 → 模型”，保留返回入口；文本和图片选择互不改变。

### 输入器布局：保留两个主要入口

推荐保留用户熟悉的 **文本模型按钮 + 图片参数按钮**：

- 文本模式：文本模型按钮；思考强度归属当前文本模型。
- 图片/Agent模式：文本模型按钮 + 图片参数按钮。图片模式补上目前隐藏的文本按钮，使移除重复控件后仍可查看和切换。
- 图片参数面板保留图片模型、比例、数量、分辨率、画质和格式；彻底删除“变体与扩写文本渠道”。
- 点击图片参数中的“图片模型”行，在当前面板内切换到“供应商 → 模型”视图；选中后返回参数页并保留其他参数。避免在一个浮层里再叠加原生 select 或多层弹窗。
- 文本触发按钮显示“模型 · 供应商”；图片参数按钮保留数量/图片模型摘要，补充来源辨认。
- 智能变体直接使用文本模型按钮当前值。无文本模型时，仅智能变体等确实需要文本的操作提示配置；普通单图和相同提示词抽样不因此禁用。
- 请求开始时固定所用模型 ID；过程中切换模型只影响下一次请求，结果仍记录原调用来源。

把图片模型再拆成第三个常驻按钮会增加输入器占用；当前没有必要，故不作为推荐布局。

### 提示词优化窗口：同组件，明确作用域

保留窗口内文本模型选择能力，并替换原生 select 为同一供应商两级选择器。推荐的作用域规则如下，属于方案建议：

1. 打开时默认“跟随工作台文本模型”，直接传入工作台选中的配置 ID，不依赖此前异步写全局默认来间接同步。
2. 用户在优化窗口主动选另一模型时，标注“仅本次优化”；不更改工作台、智能变体或全局默认。提供“恢复跟随”操作。
3. 再次打开窗口回到跟随模式；本次覆盖只在当前打开周期有效。若未来需要长期独立默认，再单独加入设置，不暗中记忆。
4. 工作台选择已失效时显示失效状态，允许在优化器显式选择替代；禁止按模型列表第一项自动补位。
5. 提交优化时固定模型配置和来源；优化期间锁定模型选择，结果标明实际使用的模型/供应商/连接。
6. 设置更新只刷新可用模型目录，不重置提示词、补充要求、已有结果或用户尚有效的本次选择；关闭后迟到的初始化/请求结果不得影响下一次打开。
7. 现有优化器使用 Radix modal。现有 `DropdownPortal` 把内容挂到 `.app`，菜单 z-index 为 1000，而优化器遮罩/窗口是1190/1200。不能直接复用这个浮层外壳：复用模型选择内容和查询逻辑，弹层挂载到当前 Dialog 内部或合适的模态层，校验焦点圈定、Escape先关选择器、焦点返回和主题继承。
8. 优化窗口 CSS 当前大量固定白底/灰蓝边框；本轮替换模型控件时一并覆盖相关明暗主题和窄窗口页脚，避免选择器看得见但底部操作被挤出。

### 当前选择与全局默认

推荐当前会话独立记住文本/图片模型配置 ID。新会话以全局默认初始化；设置页“设为默认”才改变全局默认。已有会话不被全局默认改动覆盖。

会话选择失效时保留原来源摘要并提示重选，不能按数组首项自动替换。新会话未设置默认时显示待选择。改动切换作用域需要在实施时更新会话持久化契约和迁移说明。

## 5. 同名模型与路由约束

现有数据基础可以保留：供应商 → 连接 → 模型配置，每个模型配置已有稳定 ID。数据库已限制 `(connection_id, model_id)` 唯一，因此跨连接同名本身是合法需求。

具体规则：

- 执行、选择、默认模型、最近使用、收藏、排队任务统一引用 `ModelProfile.id`。
- 外部请求的 `model` 字段才使用供应商原始 `modelId`。
- 运行时删除“原始 ID 取最近更新项”的兜底；失效配置 ID 返回明确错误。
- 审计已有调用点和历史持久化数据。历史原始 ID 只在迁移/恢复入口解析：唯一匹配可转为配置 ID；多匹配要求用户指定连接；零匹配保持失效状态。不要在每次发送时猜。
- 改名称不改变身份；改绑定连接属于改变执行来源，展示影响并确认。已有队列需锁定入队来源或使变更等待任务结束，避免排队途中改去向。
- 删除连接/供应商前展示关联模型、默认值、当前会话和未完成任务影响；建议提供暂停使用，硬删除对未完成任务明确阻止或先取消。
- 搜索回退独立配置默认搜索模型，调用前明确来源；不可用时提示选择，不按更新时间或模型列表顺序找替代品。
- 任务详情保存非敏感路由快照：配置 ID、供应商名、连接名、原始模型 ID；不保存密钥。
- 供应商同名、连接同名时提示区分；必要时显示地址主机名或短标识，不能把人类可编辑名称当唯一键。

不需要为了分组重建数据库或做全局模型去重。首轮保留每个模型配置单一用途；同端点模型同时承担文本和生图的能力建模，留作独立决策，不借本轮大改唯一约束。

## 6. 视觉与状态规范

- 主要界面字号 13–14px，模型名称 14px，辅助信息 12px；不再把关键来源/ID压到 9px。
- 设置页使用 8/12/16/24px 间距层级，减少卡片套卡片和重复边框。
- 暖白/近黑底色、语义化边框和焦点色；克制红色用于主要操作/选中强调，删除用明确文字配合危险状态。
- 状态不能只靠颜色：未配置、已配置、待验证、已验证、失败、已停用均有文字。
- 设置页提供稳定内容区，首屏加载、后台刷新、保存中分别表达。
- 按组件收拢本轮涉及的样式，避免继续向全局 CSS 叠加覆盖；不借机重构无关页面。
- 1024×720 保留必要控制，减少表格次要列并在详情查看；1440×900 和 1920×1080 使用空间但限制文本阅读宽度。
- 明暗两套主题均验证文本对比、禁用、悬停、错误、长名称与键盘焦点。

## 7. 实施顺序与验收

| 阶段 | 交付 | 依赖与验收 |
| --- | --- | --- |
| A：身份与状态 | 收紧运行时模型 ID；能力编辑保留；默认选择作用域和搜索来源明确；刷新不卸载页面 | 先写失败复现；A/B供应商同名、同供应商双连接、改名/更新时间均不改请求来源；旧数据歧义不自动选 |
| B：选择器与入口统一 | 工作台文本、图片参数内图片选择、提示词优化窗口共用供应商两级选择内容；删除变体文本重复选择；明确优化窗口局部覆盖 | 依赖 A；10供应商×50模型仍只显示当前供应商；三处入口均验收；浏览供应商不提交；模态焦点/层级、空状态、跨供应商搜索通过 |
| C：设置与导入 | 设置导航、单连接管理、独立导入窗口、批量命令、能力详情 | 依赖 A；导入100项不逐项整页刷新；重复/失败可恢复；第二页加载正常；修改名称不清空能力 |
| D：收口 | 同名/失效/长列表回归；主题尺寸检查；文档和迁移记录 | 依赖 B/C；1024×720、1440×900、1920×1080各明暗两套；通过项目全部门禁 |

先实现 A，再做用户明确要求的 B，然后完成 C。每阶段都保持桌面应用可用，任务记录沿用 `tasks/`。会话默认值作用域、运行时严格 ID、批量写入语义等获确认后再记录新 ADR，不把本方案建议写成已接受决定。

实施验收至少覆盖：

- 两供应商同 `modelId` 的文本/图片请求都命中对应 Base URL 和测试凭据。
- 同供应商下双连接同名模型可区分；刷新、改名、排序变化不影响选定身份。
- 工作台文本设为 A、优化窗口临时选 B：优化请求走 B，智能变体和对话仍走 A，全局默认不变；恢复跟随/重新打开使用 A。
- 图片模式删除变体选择后仍有统一文本入口；单图无文本模型可执行，智能变体没有文本模型时提示配置。
- 三处选择入口都支持先供应商后模型；优化窗口的选择器不会落到遮罩下，Escape先关选择器，焦点返回正确。
- 设置刷新、模式切换、会话切换和图片编辑器入口的实际路由与显示来源一致；队列中的任务不随之后的选择改变。
- 模型被删/停用/改用途后，当前会话与队列不静默选另一个供应商。
- 导入已存在项不重复创建；部分失败仍可继续处理剩余项；保存返回位置稳定。
- 未知能力不会被默认为工具调用、多图或视觉可用，模型详情修改保留既有字段。
- 供应商切换、连接筛选、空结果、长名称、100/500项列表、离线和鉴权失败都有可观察反馈。
- `npm test`、TypeScript、`npm run check:file-size`、`npm run build:app`、桌面交互及六组尺寸主题检查全部通过后才关闭实施任务。
