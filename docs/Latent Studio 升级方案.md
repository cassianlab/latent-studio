# Latent Studio 升级方案

状态：已确认，按阶段持续实施
日期：2026-09-12  
目标源码目录：`<workspace>/生图工作站`
旧版参考项目：`<workspace>/生图`

> 本文档是实施前规格。确认前不创建新仓库、不迁移旧数据、不编写产品代码。

## 1. 目标

把现有单页生图工具升级为面向个人创作者的 macOS 本地 AI 图像工作站。Latent Studio 以项目为工作边界，把文本研究、剧本文档、素材、提示词、图片生成、局部修改、Agent 编排和 Skill 执行放进同一套可追踪流程。

成功不以“功能都能打开”为标准，而以以下结果为标准：

1. 用户能选择本地文件夹创建项目，并在项目内持续管理文档、素材、会话、任务和图片版本。
2. 文本、图片和 Agent 三种模式在同一会话中切换，且共享明确的项目上下文。
3. 文本模型与图片模型可以来自不同服务商、连接和 API Key，并能在同一次 Agent 任务中协同。
4. 多图生成默认得到有明确差异的任务，而不是把同一提示词重复发送多次。
5. Agent 能调用搜索、文件、项目资料、图片模型和已启用 Skill；用户能确认、观察、暂停、纠正和恢复执行。
6. 图片可以通过可见标记和修改建议进行非破坏性重新生成，并保留完整版本关系。
7. 核心源码目标为每文件 600-800 行，任何人工维护的代码文件不得超过 1000 行。

## 2. 产品边界

### 2.1 首发范围

- 单用户、macOS、本地优先、开发模式。
- 简体中文界面，产品名称为 **Latent Studio**。
- 新建独立源码仓库；旧版保持不动，只复用经过验证的行为与算法。
- 不迁移旧历史记录。旧提示词和风格内容可以经过整理后作为新版内置资源。
- 支持文本、图片、Agent 三种工作模式。
- 支持项目、素材、文档、提示词库、记忆、任务队列、Skills 和图片标注编辑器。
- 首发文本模型范围：OpenAI、Claude、Gemini、DeepSeek、GLM、Kimi。
- 首发图片模型保留现有 OpenAI 兼容图片接口，并允许添加其他兼容连接和模型。

### 2.2 暂不包含

- 多用户、账号体系、团队协作和云同步。
- Windows、Linux、移动端和 Web 版本。
- macOS 签名、公证、安装包、自动更新和正式发布流程。
- Word 式复杂排版、原格式无损编辑和多人文档协作。
- 音视频生成、音视频转录和 Excel 工作流。
- 完整 Photoshop 类像素编辑、图层合成和专业调色。
- Agent 任意扫描项目外磁盘、静默安装运行时或静默执行未信任代码。

## 3. 核心术语

- **项目**：用户选择的本地文件夹，是文档、素材、会话、任务、输出和项目记忆的边界。
- **会话**：项目内一条连续上下文；可随时切换文本、图片和 Agent 模式。
- **服务商类型**：OpenAI、Anthropic、Gemini 或 OpenAI 兼容协议等 API 类型。
- **连接配置**：一组名称、服务商类型、Base URL、API Key 和并发限制。同一服务商可有多个连接。
- **模型配置**：一个实际可选模型，声明文本或图片类型、模型 ID、能力和绑定连接。
- **任务计划**：Agent 或智能批量生成产生的可检查任务集合。
- **任务**：一次可排队、执行、取消和重试的模型或 Skill 调用。
- **素材**：项目中的图片或文件，可标记为角色、场景、道具、风格参考、普通参考图或生成结果。
- **提示词资产**：可直接插入的提示词、带变量的模板或可追加的风格片段。
- **Skill**：可由文本或 Agent 模式受控调用的能力包，可包含 `SKILL.md`、脚本、参考资料和资产；图片模式不调用 Skill。
- **记忆**：可编辑、可停用的稳定偏好或项目约束，不等于完整聊天记录。
- **图片版本**：从原图或某个已有结果派生的新图片，保留来源、参数和父子关系。

## 4. 信息架构

### 4.1 启动页

- 最近项目列表。
- 新建项目：必须由用户选择文件夹。
- 打开项目：选择已有 Latent Studio 项目目录。
- 项目缺失、移动或权限失效时显示修复入口，不自动创建替代项目。

### 4.2 项目内导航

左侧固定窄导航：

1. 工作台
2. 素材库
3. 项目文档
4. 提示词库
5. Skills
6. 任务中心
7. 项目设置

全局模型与应用设置从顶部全局入口进入独立页面，不塞入工作台弹窗。

### 4.3 工作台

- 中间区域显示对话消息、计划卡、任务状态和生成结果。
- 底部固定大型输入器，参考用户提供的截图，但不照搬其品牌和布局细节。
- 输入器底部提供：添加文件、选择项目素材、选择提示词、`@` 引用、模式切换、执行方式、文本模型、图片模型和发送。
- 右侧可折叠检查器显示当前任务参数、参考素材、实际路由、版本信息和高级选项。
- 常用参数直接可见，高级参数按需展开。

### 4.4 三种模式

#### 文本模式

- 普通对话、流式输出和停止生成。
- 使用当前文本模型。
- 支持模型原生联网搜索。
- 支持读取当前项目资料和用户明确选择的外部文件。
- 可把回答保存为项目文档、提示词、模板或记忆候选。
- 默认不绑定 Skill；用户可用 `/Skill` 显式激活当前轮的受控 Skill，但文本模式不自动匹配 Skill，也不暴露生图工具。

#### 图片模式

- 使用当前图片模型生成或参考图重绘。
- 可以独立选择一个文本模型进行提示词优化和智能变体规划。
- 支持单张生成和四种批量类型：同提示词抽样、智能变体、分镜任务、独立创意。
- 多图任务经规划后并发执行，不串行等待每张完成。
- 同提示词批量必须由用户主动选择，不能作为默认行为。
- 图片模式不调用 Skill。

#### Agent 模式

- 使用当前文本模型理解目标、制定计划并执行工具调用。
- 可以使用与当前文本模型不同连接的图片模型。
- 可以调用项目启用的 Skill。
- 默认不绑定 Skill；用户可用 `/Skill` 显式激活当前轮，Agent 也可按当前请求自动匹配已信任和授权的 Skill。
- 提供“确认后执行”和“自动执行”两种方式。
- 自动执行仍必须生成并保存计划，不允许绕过日志、任务队列和权限检查。

## 5. 关键用户流程

### 5.1 创建项目

1. 用户选择一个文件夹。
2. 应用检查写入权限和现有项目标识。
3. 用户填写项目名称和可选说明。
4. 应用按需创建项目结构，不移动文件夹中的原文件。
5. 项目进入最近项目列表并打开工作台。

### 5.2 文本研究

1. 用户选择文本模型并提出问题。
2. 若请求需要联网，优先使用当前模型的原生搜索能力。
3. 当前模型不支持搜索时，调用用户配置的默认搜索模型。
4. 搜索结果保留标题、URL、来源模型和查询时间。
5. 用户可把回答保存为文档、剧本、提示词或记忆候选。
6. 没有可用搜索模型时明确提示，禁止伪造已联网结果。

### 5.3 智能多图生成

1. 用户输入目标、选择批量类型、数量、文本模型和图片模型。
2. 文本模型返回结构化任务计划，每项包含独立提示词、不变量、变化维度、参考素材和输出规格。
3. 系统校验任务数量、字段、模型能力和参考图限制。
4. 确认模式允许用户编辑、删除和排序；自动模式直接入队。
5. 队列按连接的并发设置同时执行图片任务。
6. 单项失败不取消其他任务，最终显示成功、失败和可重试项。

### 5.4 Agent 执行与调整方向

1. Agent 输出可编辑计划卡，包含步骤、模型、Skill、素材、图片数和预计调用次数。
2. 确认模式等待用户批准；自动模式直接执行。
3. 用户提出修改意见时立即停止派发新任务，并尝试取消正在运行的请求。
4. 已完成结果保留但标为“旧方向”。
5. Agent 只重写未完成部分，形成新的计划修订。
6. 确认模式再次等待批准；自动模式恢复执行。
7. 计划、修订原因和实际执行路径全部可追踪。

### 5.5 标注图片后局部修改

1. 用户从生成结果或素材库打开图片编辑器。
2. 用户在非破坏性标注层上使用画笔、擦除、箭头、矩形和文字指出修改区域。
3. 用户填写修改建议，可调用文本模型优化描述。
4. 应用导出带可见标记的合成图。
5. 图片模型支持多参考图时发送原图和标注图；只支持单图时发送标注图。
6. 提示词明确标记颜色和区域只用于说明修改位置，要求输出中移除标记。
7. 新结果保存为当前图片的子版本，原图、标注数据和实际请求均保留。

### 5.6 快速保存提示词

- 每次图片生成记录原始提示词、优化提示词和实际执行提示词。
- 用户可从消息、任务卡和图片详情一键保存。
- 保存时选择全局或当前项目，并选择提示词、模板或风格类型。
- 同名内容不静默覆盖，提供新版本、另存为或取消。

## 6. 项目与数据设计

### 6.1 项目目录

```text
项目目录/
├── project.json
├── documents/
├── assets/
├── outputs/
└── .latent-studio/
    └── project.db
```

- `project.json` 保存可读的项目身份和格式版本。
- 文档以 Markdown 或原始导入文件保存。
- 项目素材和输出是普通文件，可被其他软件直接读取。
- 项目数据库保存会话、任务、关系、索引、记忆和图片版本元数据。
- 所有写文件操作使用临时文件加原子替换。
- 删除素材和输出默认进入系统废纸篓；删除元数据前检查引用关系。

### 6.2 全局数据

全局数据存放在 Electron 应用数据目录：

- 全局数据库：连接、模型、全局提示词、全局记忆、Skill 元数据、最近项目。
- Skills 目录：已安装的全局 Skill 副本。
- API Key：通过 Electron `safeStorage` 加密后保存，绝不进入项目目录、日志或渲染进程。

### 6.3 数据库

- 使用 Electron 44 所带 Node.js 24 的内置 `node:sqlite`，已确认运行时可用，不增加原生 SQLite 依赖。
- 数据访问只发生在主进程，通过窄接口暴露给渲染进程。
- 全局数据库与项目数据库分别维护 schema 版本和迁移。
- 对话、计划、任务和图片版本使用稳定 ID，不依赖数组位置。

## 7. 模型与连接体系

### 7.1 连接配置

每个连接独立保存：

- 名称和服务商类型。
- Base URL 和加密 API Key。
- 可用操作和协议。
- 用户设置的最大并发数。
- 超时、启用状态和可选备注。

不根据服务商名称硬编码并发。新连接使用保守默认值 `1`，由用户测试后人工调整。应用可另设全局并发上限，实际并发取全局上限与各连接上限共同约束。

### 7.2 模型配置

- 强制分为文本模型和图片模型。
- 每个模型绑定一个具体连接，因此 Claude 与 GPT 可以同时使用不同服务商和不同 Key。
- 模型选择器按类型展示，并支持收藏、置顶和最近使用。
- 同一模型 ID 可以创建多个配置，分别绑定不同连接，并使用不同显示名称。
- 模型能力至少包括：流式文本、工具调用、视觉输入、原生搜索、参考图、多参考图和标注图重绘。

### 7.3 模型列表

- 连接支持列表接口时可以一键获取模型。
- 获取结果进入待选择列表，不自动全部启用。
- 始终支持手动添加模型。
- 自动获取只能确认模型 ID，不能可靠推断能力；能力由已知规则、用户确认或适配器声明补齐。

### 7.4 适配器

建立窄接口，业务层不依赖具体 SDK：

- OpenAI 协议适配器。
- Anthropic Messages 适配器。
- Gemini GenerateContent 适配器。
- OpenAI 兼容适配器，覆盖 DeepSeek、GLM、Kimi 和代理服务。
- 图片生成与参考图编辑适配器。

OpenAI、Anthropic 和 Gemini 优先使用官方 SDK；兼容服务复用 OpenAI SDK并传入独立 Base URL。适配器统一流式事件、工具调用、取消、错误分类、模型列表和能力声明。

### 7.5 路由

- 文本模式使用用户当前选择的文本模型。
- 图片模式分别记住文本优化模型和图片模型。
- Agent 计划中的每一步显式记录实际模型配置和连接。
- 当前文本模型不支持搜索时使用默认搜索模型。
- 自动备用连接默认关闭；用户可为单个模型配置显式备用顺序。
- 切换连接必须记录原因，不静默改变费用或数据去向。

## 8. 任务队列与状态机

### 8.1 状态

任务计划状态：

`draft → awaiting_approval → queued → running → completed | partial | failed | cancelled`

运行中还允许进入：

- `pausing`
- `paused`
- `replanning`

单项任务状态：

`pending → running → completed | failed | cancelled`

失败任务经人工或策略批准后回到 `pending`，保留原尝试记录。

### 8.2 调度规则

- 调度器按连接分别维护并发令牌。
- 一个连接被限流时不阻塞其他连接。
- 429、连接重置和明确的临时服务错误可有限重试。
- 鉴权、参数和能力错误不自动重试。
- 重试保留原错误、尝试次数和实际延迟。
- 批量任务允许部分成功。
- 关闭窗口或重启应用后恢复未完成任务，但恢复执行前向用户说明状态。

### 8.3 取消语义

- 停止派发尚未开始的任务。
- 对运行中的 SDK 请求发送取消信号。
- 明确提示取消不保证服务商停止计费。
- 已落盘结果不因取消而删除。

## 9. Agent 设计

### 9.1 Agent 工具

首发允许：

1. 模型原生联网搜索。
2. 读取当前项目文件和用户明确选择的外部文件。
3. 检索项目文档、素材、提示词和记忆。
4. 调用项目启用的 Skill。
5. 创建、修改和执行图片任务计划。
6. 保存项目文档、提示词、模板和记忆候选。
7. 查询、暂停、取消和重试任务。

Agent 不获得通用磁盘扫描工具。Skill 脚本执行是单独的权限系统，不等于 Agent 自动拥有任意命令权限。

### 9.2 执行循环

- Agent 使用统一的文本模型接口和结构化工具调用。
- 每次运行设置最大步骤、最大工具调用数和可取消信号。
- 工具输入在进入业务前进行运行时校验。
- 工具结果以结构化数据回传，不通过解析展示文本驱动业务。
- 计划修订只替换未完成部分，已完成步骤不可静默改写。

### 9.3 可观察性

用户可以看到：

- 当前步骤和状态。
- 使用的文本模型、图片模型和连接。
- 调用的 Skill 名称和 UI 备注。
- 搜索查询和来源。
- 任务耗时、尝试次数和失败原因。
- 计划修改前后的版本。

敏感头、Key、完整本地绝对路径不进入可导出日志。

## 10. Skill 系统

### 10.1 格式与来源

兼容 Agent Skills 文件夹结构：

```text
skill-name/
├── SKILL.md
├── scripts/
├── references/
└── assets/
```

支持两种接入方式：

- **链接**：引用已有 Skill 目录，不复制；源目录变化后重新扫描。
- **安装**：复制到 Latent Studio 全局或项目专用 Skills 目录。

UI 允许设置显示名称、备注、标签、启用状态和项目授权，不改写 Skill 原始名称。文本与 Agent 模式默认不绑定 Skill；用户可在任意一轮输入 `/Skill` 显式激活当前轮 Skill，文本模式仅使用显式选择，Agent 还可从合规候选中自行判断。

### 10.2 调用准确性

- 安装时解析名称、描述、权限声明和所需资源。
- 自动路由向 Agent 提供全部已启用、已信任且获当前项目授权的精简元数据；Agent 明确选择并记录理由后，系统才读取对应完整指令。
- 手动 `/Skill` 选择覆盖同一 Skill 的自动路由，并与 Agent 本轮匹配到的其他必要 Skill 合并；历史 Skill 快照只作为只读上下文。
- 执行记录展示实际读取的 `SKILL.md` 版本和调用参数。
- 为候选暴露、越权拒绝、显式优先、指令按需加载和选择理由留痕建立可回放测试，防止漏调和误调。

### 10.3 脚本执行

首发支持 Python、Node.js 和 Shell 脚本；不自动安装缺失运行时。

执行模式可在设置中选择，并允许每个 Skill 覆盖：

- **完全信任**：确认安装后以当前用户权限运行。
- **受控执行**：首次执行或权限变化时确认；清理敏感环境变量；限制工作目录、超时、输出大小和并发；通过参数数组启动明确文件，不拼接 Shell 命令字符串。

受控执行不是完整操作系统沙箱，界面必须明确说明。Skill 来源、文件哈希或权限声明变化后自动撤销信任。进程必须可取消，并记录退出码和脱敏后的标准输出/错误。

## 11. 提示词库

### 11.1 类型

- 提示词：可直接插入或执行。
- 模板：包含显式变量和默认值。
- 风格：追加到已有提示词的片段。

### 11.2 范围与管理

- 全局与项目两种范围。
- 分类、标签、收藏、搜索和版本记录。
- 原始提示词、文本模型优化结果、每个图片任务的最终提示词分别保存。
- 快速保存入口出现在文本消息、图片任务卡和图片详情中。
- 保存到项目时记录关联会话、任务和图片；保存到全局时去除项目私有引用。

## 12. 项目素材与文档

### 12.1 素材

- 来源包括用户导入、外部临时引用和生成结果。
- 外部文件默认只临时读取，用户选择“保存到项目”后才复制。
- 可标记角色、场景、道具、风格参考、普通参考图或生成结果。
- 角色和场景支持名称、描述、固定提示词和多张参考图。
- 列表使用缩略图和虚拟化，原图按需解码。

### 12.2 文档

- 支持 Markdown、TXT、JSON、PDF、Word 和常见图片输入。
- Markdown、TXT 和结构化剧本可在应用内编辑。
- PDF 和 Word 在本地提取文本后生成项目文档，不承诺保留原排版。
- 图片通过具备视觉能力的文本模型理解。
- 原始文件和提取结果分别记录，避免无法追溯来源。

### 12.3 剧本与分镜

- 剧本首先是普通 Markdown 文档。
- Agent 可将剧本解析为场景、镜头、角色、地点、画面描述和提示词组成的分镜表。
- 分镜表可人工编辑，再转换为图片任务计划。
- 结构化分镜是派生数据，不能覆盖原剧本文档。

## 13. 记忆

### 13.1 范围

- 全局记忆：长期画面偏好、常用比例、禁止元素和通用工作习惯。
- 项目记忆：角色外观、世界观、场景规则和项目约束。

### 13.2 写入规则

- 用户明确说“记住”时创建待确认记忆。
- Agent 可从对话中建议稳定偏好，但默认不能静默写入。
- 自动写入与 Agent 自动执行分别设置，不能互相隐式开启。
- 全局与项目自动写入分别授权。
- 每条记忆保存来源、创建时间、更新时间、状态和最近使用时间。
- 用户可以查看、编辑、停用和删除。

## 14. 图片查看与编辑

### 14.1 高性能预览

- 列表和对话使用缩略图，原图仅在需要时加载。
- 解码和缩略图生成不阻塞渲染主线程。
- 缩放和平移使用稳定变换，拖动期间不触发布局重排。
- 支持适应窗口、100%、滚轮缩放、拖动、键盘切换和全屏。
- 大列表采用虚拟化，图片切换不改变预览容器尺寸。
- 浏览器对象 URL 及时释放；失败状态可重试且不破坏其他图片。

### 14.2 标注编辑器

工具包括：

- 选择和移动标注。
- 自由画笔及大小、硬度、颜色和透明度。
- 擦除标注。
- 箭头、矩形和文字说明。
- 撤销、重做、清空。
- 缩放、平移、适应窗口。
- 裁剪、旋转和翻转。

编辑器采用底图层与标注层分离的非破坏性模型。原型阶段首选 Konva/React Konva，因为其 React 集成、分层对象、自由绘制、裁剪和导出能力与需求匹配；正式锁定前必须用大图、长笔迹和频繁撤销进行性能验证。若不达标，再评估 Fabric.js。

### 14.3 提交给图片模型

- 导出标注后的扁平图片，标注数据另存为可继续编辑的 JSON。
- 多参考图模型默认发送原图和标注图；单参考图模型发送标注图。
- 请求中附带修改建议和固定的标注解释协议。
- 不依赖供应商原生 mask 字段，也不把整图重绘伪装成严格像素级修补。
- 输出中若仍出现标记，作为普通生成结果保留并提示用户重新生成，不覆盖原图。

### 14.4 版本链

- 所有编辑结果是新版本，原图不变。
- 保存父版本、实际提示词、模型、连接、参考图、标注和生成参数。
- 任意版本可设为新起点。
- 支持并排对比和快速回到父版本。
- 标注文件不默认显示为普通素材。

### 15.2 进程边界

#### 主进程

- 项目与全局数据库。
- 文件系统与图片处理。

- 模型适配器和请求执行。

- 只暴露类型明确的业务命令和订阅。

- 页面、交互、编辑器和只读视图状态。
- 不保存 API Key，不直接调用外部模型 API。
- 不直接读写项目数据库。

### 15.4 文件规模规则

- 人工维护的 TS、TSX、JS、CSS 和脚本目标 600-800 行。

- React 页面目标不超过 500 行，复杂状态进入 reducer、hook 或领域服务。
- 静态提示词数据按类别拆分，不再形成单个近千行目录文件。
- 生成文件和第三方代码不计入限制，但必须位于明确的生成目录。
- 不因行数机械拆分；拆分点必须对应职责、状态所有权或测试边界。

## 16. UI 与品牌

### 16.1 品牌

- 产品名：Latent Studio。
- Logo 母版：`<local-assets>/Latent Studio 优化 App 图标.png`。
- 当前母版为 2048×2048 RGB PNG、无透明通道。
- 实施时生成 macOS 所需尺寸并检查 16、32、64、128、256、512 和 1024 像素可读性。

### 16.2 设计方向

- 浅色：暖白背景、炭黑信息层级、红色品牌强调。
- 深色：近黑背景、中性灰层级、低饱和红色强调。
- 主操作使用高对比中性色，避免品牌红与危险操作混淆。
- 不使用大片渐变、装饰性卡片堆叠或紫蓝色 AI 套路配色。
- 中文使用系统字体，不依赖网络字体。
- 常规过渡 180-240ms，使用 transform 和 opacity，支持减少动态效果。
- 所有图标使用 Lucide；复杂交互 Tooltip 使用 Radix，不依赖原生 `title`。

### 16.3 UI 技术组合

- shadcn/ui 提供可拥有源码的组件结构。
- Radix 提供无障碍交互原语。
- Tailwind 和 CSS 变量承载设计令牌。
- Motion 只用于页面切换、任务状态、展开收起和必要的共享元素过渡。
- UI UX Pro Max 用于原型阶段生成候选设计规则。
- Vercel Web Design Guidelines 和 React Best Practices 用于验收审计。

## 17. 原型阶段

### 17.1 原型性质

- 在新仓库的独立 `prototype/ui-shell` 分支创建。
- 使用完整模拟数据，不调用真实模型、不读写正式数据库、不执行 Skill。
- 原型是交互决策依据，不直接视为生产代码。
- 经确认的设计令牌、组件行为和页面流程再进入正式实现。

### 17.2 必须覆盖

1. 启动页和项目创建。
2. 三模式统一输入器。
3. 文本对话与搜索引用。
4. 图片生成、智能变体和任务卡。
5. Agent 计划确认、自动执行、暂停和调整方向。
6. 素材选择与结构化素材详情。
7. 提示词快速保存。
8. 模型连接、模型列表和能力设置。
9. Skill 链接、安装、备注、授权和信任模式。
10. 任务中心。
11. 图片全屏预览、版本对比和标注编辑。
12. 全局与项目记忆管理。

### 17.3 原型验收

- 用户能在不看说明的情况下完成“创建项目 → 选素材 → 智能生成 4 图 → 修改方向 → 标注局部重绘 → 保存提示词”。
- 常用操作不被高级配置淹没。
- 文本模型与图片模型的独立选择清楚可见。
- 计划、任务和最终图片之间的关系不会混淆。
- 浅色和深色在 1024×720、1440×900 和宽屏下无重叠、截断和不可达控件。
- 键盘焦点、减少动态效果和缩放后的文字布局可用。

## 18. 测试策略

### 18.1 原则

- 测试用户可观察行为，不测试组件内部变量是否被赋值。
- Bug 修复必须先添加能复现问题的失败测试。
- 外部模型测试使用协议夹具和本地假服务，CI 不调用收费 API。
- 关键流程优先在最高可用接口测试，避免每层重复同一断言。

### 18.2 测试边界

1. **应用用例测试**：通过假模型、临时项目目录和内存时钟验证完整任务流程。
2. **适配器契约测试**：验证各协议的请求映射、流式事件、工具调用、取消和错误分类。
3. **队列状态机测试**：并发、公平调度、暂停、恢复、重规划、部分成功和重启恢复。
4. **项目存储测试**：原子写入、数据库迁移、移动项目、文件缺失和引用保护。
5. **安全测试**：IPC 输入校验、路径越界、SSRF、日志脱敏、Skill 环境变量和信任撤销。
6. **图片处理测试**：严格尺寸、格式、缩略图、标注导出、旋转裁剪和版本关系。
7. **渲染测试**：三种模式、快速保存、素材选择、模型选择和 Agent 干预。
8. **Playwright Electron 测试**：核心端到端流程、键盘操作和窗口尺寸。
9. **视觉回归测试**：浅色、深色、加载、空、错误、长文本和大批量任务状态。
10. **性能测试**：大图缩放拖动、1000 项素材列表、长笔迹、连续撤销和并发任务更新。

### 18.3 质量门禁

- TypeScript、lint、单元测试和核心 E2E 全部通过。
- 人工代码文件不得超过 1000 行。
- 生产代码不包含未说明的 `any`、空 `catch`、明文 Key 或任意 Shell 拼接。
- 图片预览拖动与缩放期间不发生明显掉帧；具体阈值在原型基准机上记录后锁定。
- Agent 和 Skill 的每次外部动作可追踪、可取消或明确说明不可取消。

## 20. 主要风险与控制

### 20.1 范围过大

控制：先批准 UI 原型；之后按纵向阶段逐步替换模拟端口，每阶段保持应用可运行，不进行跨全仓库的大爆炸重构。

### 20.2 多模型协议差异

控制：能力显式声明、协议适配器和契约测试；UI 不展示连接不支持的操作；不通过模型名称猜能力。

### 20.3 多图仍然相似

控制：规划输出显式分离不变量与变化维度；同提示词批量只允许用户主动选择；保存每张实际提示词以便复盘。

### 20.4 Skill 代码风险

控制：链接/安装来源可见、哈希变化撤销信任、敏感环境变量清理、超时和取消；界面明确说明完全信任与受控执行都不等于操作系统级沙箱。

### 20.5 图片编辑性能

控制：成熟 Canvas 库、底图与标注分层、缩略图、按需解码、固定视口和专项性能门禁；不移植画布项目的大型编辑器组件。

### 20.6 本地项目损坏

控制：schema 版本、原子文件写入、数据库事务、废纸篓删除、启动完整性检查和可恢复错误提示。
