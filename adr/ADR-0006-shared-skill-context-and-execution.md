# ADR-0006 共享 Skill 上下文与本轮执行权限

- 状态：accepted
- 日期：2026-09-15

## 决策

文本与 Agent 模式的输入器默认不绑定 Skill。用户可以在任意一轮用 `/Skill` 显式激活一个 Skill；Agent 模式还可以从全部已启用、已信任且已获当前项目授权的 Skill 中自行选择。文本模式不自动匹配 Skill，显式选择时也不附加其他自动匹配项。

Agent 首先只接收候选 Skill 的 ID、名称和简短描述。它必须通过受控工具提交 Skill ID 与选择理由，主进程验证候选资格后才读取完整 `SKILL.md`，并在下一次模型调用中提供指令。显式 `/Skill` 直接进入当前轮激活列表并优先提供完整指令；Agent 仍可另选其他必要候选。生产路由不使用本地关键词规则预先排除候选。

会话保留已调用 Skill 的指令快照和模型已见的工具结果，供后续轮理解前文。内容哈希未变时复用快照，不重复读取 `SKILL.md`。历史快照只是只读上下文；只有当前轮显式选中或由 Agent 本轮自动匹配的 Skill 才能执行脚本。上下文压缩覆盖到的早期 Skill 细节可以只保留在压缩摘要中。

文本模式使用同一受控 Agent 执行器读取附件、参考图和显式 Skill，但不向模型暴露创建或控制图片任务的工具。Skill 脚本仍在 Electron main 进程中经原有信任、项目授权、路径和超时边界执行，渲染进程不获得通用文件系统或命令执行能力。

## 代价与边界

- 同一会话可以累积多个 Skill 快照，因此它们与普通对话共用 258k token 窗口，超过阈值时按会话压缩规则处理。
- 0.6.0 的压缩由会话上下文准备器执行摘要式压缩并保留完整原始消息；OpenAI Responses 官方 Compaction 能力探测与接入仍属于后续工作，不能把当前本地摘要标记为官方压缩。
- 已安装 Skill 发生更新不会改写旧轮的指令语义；后续再次激活时，新内容哈希会更新该 Skill 的会话快照。
- 候选元数据会占用少量上下文；完整指令只为本轮选中的 Skill 加载，并继续按内容哈希复用。
- 用户在文本模式显式运行 Skill 也可能触发脚本副作用，所以不降低现有信任和授权要求。
