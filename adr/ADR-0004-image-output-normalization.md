# ADR-0004 图片输出规格标准化

- 状态：accepted
- 日期：2026-09-14

## 决策

使用 Sharp 在 Electron 主进程验证供应商返回的真实图片，并将落盘结果统一为任务要求的尺寸及 PNG/JPEG/WebP 格式。文件后缀以实际编码格式为准，不继承供应商 URL 后缀。尺寸不匹配时采用 `cover` 和 `attention` 裁切；输出同时记录供应商原始尺寸和格式，供规格偏差审计。

普通图片任务、Agent 可编辑计划和自动工具链传递同一组尺寸、质量和输出格式。适配器不向 DALL-E 2/3 发送不支持的 `output_format`，但本地仍执行输出格式标准化。

### 2026-09-14 规格修正

- `size` 仅表示供应商请求尺寸；新增 `outputSize` 表示本地导出目标，适配器绝不将其发送给供应商。
- 1K / 2K / 4K 指约 1024 / 2048 / 4096 像素长边；使用比例的整数倍保持精确画幅，超宽比例可能略微偏离长边标称值。16:9 的 4K 导出为 4096x2304，并非 UHD 3840x2160。
- 新任务采用明确导出目标；历史任务未记录 `outputSize` 时继续使用原 `size`，不改写历史文件。
- 图片计划的共享不变量随每个镜头请求发送；自动工具链通过 `invariants` 字段声明同一组约束。这提高约束传递完整性，不保证模型内容一致。

## 代价与边界

- Sharp 是新增原生运行时依赖；桌面构建和 Electron 启动必须验证其加载。
- `cover` 可能裁掉画面边缘；放大仅进行重采样，不创造细节，不等于 AI 超分、内容一致性或审美质量提升。
- 质量档位是发送给供应商的请求参数，不是本地可保证的画质评分；不支持的采样步数、CFG 和随机种子仍不可伪装成已生效。
- 真实服务商画质和内容遵循程度需要人工以工作样本验收，单元测试只保证协议、图片规格和状态行为。
